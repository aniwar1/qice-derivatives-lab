# Qice Derivatives Lab · 期策

**本地运行的商品期货与买方期权研究工作台。** 期策把行情取证、Codex 分析、策略校验和结果回看接成一条研究流程。每次分析固定品种与时点，记录可用证据及缺口，再由程序校验结论是否满足发布条件。当前配置覆盖中国商品市场的 22 个品种。

`React · TypeScript`　`FastAPI · Python`　`SQLite`　`DuckDB`　`Codex CLI`

## 快速体验

需要 macOS 或 Linux、Python 3.12+、Node.js 22+ 和 pnpm。首次启动会联网安装依赖和构建界面。

```bash
git clone https://github.com/aniwar1/qice-derivatives-lab.git
cd qice-derivatives-lab
./start.sh
```

打开 <http://127.0.0.1:8000>。首页显示三个模拟组合的半年滚动收益曲线。新安装可先浏览三套策略计划和 22 个品种的研究提纲。导入或完成本机半年仿真后即可查看真实模拟账目。要采集行情和生成研究结论，先安装 Codex CLI 并执行 `codex login`，再选择「运行全市场研究」或在品种页点击「运行单品种分析」。

服务只监听回环地址，按 `Ctrl+C` 停止。端口冲突时可用 `./start.sh --port 8080`。可用 `PYTHON_BIN=python3.12 ./start.sh` 指定解释器。行情查询和生成新策略需要联网，已保存的策略可离线回看。

## 工作台

| 入口 | 能看到什么 |
| --- | --- |
| 半年滚动基线 | 同一起点比较 A、B、C 的累计收益率与权益。各组可展开策略计划、期末持仓、每日判断和模拟成交。盘中单列上次结算持仓的参考浮动。 |
| 品种研究 | 搜索 22 个品种，查看实际月份合约走势图、供需与催化观察项、技术与持仓证据，以及该品种在半年窗口内的策略记录。 |
| 半年回测档案 | 查看原始批次的逐日判断、风险预算和执行回执。切换品种可核对当时的原文、期货合约和期权腿。 |
| 频率与期限对照 | 比较原版、首选和主备方案，在同一事件下对照主力月和远月双买成本，回看采用各版本的证据。 |
| 研究档案 | 查看研究记录、下载行情原件、核对合格机会，并按指定时点回放。 |

### 半年曲线如何更新

每天按北京时间向前推六个自然月，用该日或此前最近一个真实收盘作为 0% 基准。比如 2026 年 11 月 22 日对应 5 月 22 日收盘。窗口滚动时三组一起重设图表基准，现金、在手合约及其成本沿原模拟账户接续。权益视图按 20 万元统一起点折算，期间实际模拟盈亏另列。

后台随本机服务运行，浏览器关闭后仍会检查。交易日从 16:00 起读取交易所日表并核对持仓。16:00 至 20:00 预先保存当时能取得的研究材料，20:00 至 21:00 用已封存的资料形成下一交易日的 Agent 判断。停机错过盘前窗口会记入缺口，当天仅执行原有持仓的既定退出规则。若持仓报价或到期处理仍待核实，正式曲线停在最后一个可核实的收盘。开市时，页面每分钟刷新，分别显示新鲜双边盘口能覆盖的持仓腿及参考浮动。

历史仿真位于 `local-data/agent-study/`，接续账户、交易所原件、盘前判断和日结保存在 `local-data/rolling-six/`。在已安装依赖的仓库中可以运行一次与后台相同的检查：

```bash
PYTHONPATH=backend:. .venv/bin/python -m scripts.rolling_update --workspace "$PWD"
```

## 半年 Agent 仿真

每天收盘资料整理后，系统为 22 个品种冻结同一个信息截止点。一个独立的 Codex 会话同时审阅三个策略，分别给出等待或入场、合约、预算、理由和失效条件。模型只能看到当日输入。程序保存输入摘要和模型回执，再按交易日顺序结算三个各自以 20 万元起步的模拟账户。隔离会话之间不共享账户历史；现金余额、已有仓位和流动性约束在结算时生效。

| 模拟组合 | Agent 需要回答的问题 |
| --- | --- |
| A · 多因子方向买权 | 直接供需证据和可追溯消息能否解释同一方向？前二十个交易日区间内的目标情景，扣除压力成本后还有多少空间？单笔权利金预算上限为净值的 0.5%。 |
| B · 技术择强买权 | 实际合约的趋势、波动和成交能否支持买权？基本面或消息的反证是否足以让组合减仓或等待？ |
| C · 事件驱动宽跨式 | 市场在此刻是否已经知道事件时间？拟持有期能否覆盖事件？历史波动范围和两腿权利金能否支持同时买入虚值看涨和看跌？ |

资料只采纳发布主体在其职责范围内公开的原件。交易所日行情和仓单用于报价、成交与可交割库存，国家统计局和农业农村部原稿用于现货、产业与预定事件，发行人披露补充相应企业的产销数据，中期协各期统计表提供市场成交与月末总持仓。媒体转载仅用于寻源。每条事实保留关联品种、直接或间接关系、可用时点、采集时点和原件摘要。会员席位与市场汇总可包含客户仓位，本批次具名机构自营方向均为未知。后续研究会区分原始事实与发布者的解读，说明哪些参与者可能受益或承压，以同一合约当时的价格、成交量和持仓反应检验消息是否已经计价。资金动机缺少直接证据时列为假设，并写明什么情况会推翻它。

本机参考批次为 2026-05-21 至 2026-11-20，共 125 个交易日。以**前一交易日北京时间 20:00** 冻结资料，含节假日前后的同一规则。交易所的明确修订时间、中期协正文及附件的版本时间同样受截止点约束。对首次发布后是否发生过未留档的修改，现有档案仍有不确定性。上期所和郑商所 14 个品种取得完整逐日原表。广期所有部分期货快照，大商所和广期所共 8 个品种缺可核验的逐日期权链。按前日实际月份、虚值程度、到期距离及成交量筛选后，可选腿的天数还会减少。

组合可连续空仓。B 如缺少基本面或消息引用，单笔预算压至 0.5%。单笔权利金最高占前日净值 1%，在手成本合计最多 8%。仿真用实际合约的交易日开盘价，每腿每边计 1% 不利滑点及每手 3 元费用。日线无法验证开盘盘口深度、双腿同步成交或盘中触价先后。页面分别显示模型提议、风控拦截和模拟成交。

### 在本机复跑

下面的命令在仓库根目录执行，先完成首次启动并登录 Codex CLI。完整回放将为 125 个交易日分别运行模型。原件及回执占用的磁盘空间和模型调用由当前本机账户承担。

```bash
export PYTHONPATH=backend:.
study_dir="local-data/agent-study/2026-05-21_2026-11-20"
.venv/bin/python -m scripts.collect_replay_market --out "$study_dir/market" --start 2026-04-01 --end 2026-11-20
.venv/bin/python -m scripts.collect_monthly_statistics --out "$study_dir/monthly" --start 2026-05-01 --end 2026-11-20
.venv/bin/python -m app.agent_sources --archive-root local-data/agent-sources --start 2026-05-15 --end 2026-11-20 --official-urls config/agent_source_seeds_2026.txt
.venv/bin/python -m app.agent_source_supplement --out local-data/agent-sources/supplement
.venv/bin/python -m scripts.agent_replay --study "$study_dir" --sources local-data/agent-sources --start 2026-05-21 --end 2026-11-20
```

采集器按日期和来源记载缺口。可通过官方地址清单补采已脱离目录分页的原稿，或用 `--gfex-history` 导入已锁定摘要的广期所历史期货快照。依赖当前网站可用性的重新采集，可能得到不同覆盖。要复核同一批次，请保留原始 `market/`、`monthly/`、来源原件及 `receipts/`。回执未齐时，权益只计算从期初开始的连续交易日。

## 出手频率与双买期限

在同一份冻结档案上，系统分别回答三个问题。每项实验独立出账。

| 问题 | 如何对照 |
| --- | --- |
| 成本和仓位上下文能否改善 Agent 的选品？ | 模型按前收看到每个整手的权利金、50 / 100 个基点预算可买的手数、带来源和日期的同口径仓单变化、证据新鲜度及压力情景。程序在下一开盘前用模拟账户逐组筛查。首选版只审第一项，主备版按同一份模型回执依次审两个不同品种，开盘未成交即结束当天委托。 |
| 更频繁尝试固定信号能多赚多少？ | 固定合约趋势、0.5% 预算、持有期与费用，分别按每天和每五个交易日筛选。列出低频的五个起始相位，无论盈亏都计入。结果可与 Agent 账本分别查看。 |
| C 策略是否应优先远月？ | 对事先已知的国家统计局事件，按前日持仓量确定主力期货，并按各自月份的期货价格匹配虚值看涨和看跌。每种结构独立分配 2,000 元，核对四条腿的价格、成交量与期限。按独立事件等权，分母统一为预算。另按期权全行权价的看涨看跌合计持仓量重新定义主力月。用实际到期日、前收和零利率 Black-76 模型估计固定标的与隐波时的一天损耗，与实际盈亏分列。 |

策略升级要求该组开仓数增加、全期与最后 42 日净损益均提高、最大回撤增加不超过 0.5 个百分点。主备版还须分别超过首选版和原版。远月取得候选优先资格的条件是全期至少 10 个可配对的独立事件，后段至少 5 个，并在两个区间都有正的远月平均收益和相对主力的优势。最后 42 日沿用前段现金与持仓，属于同一历史窗口。留存的回执支持独立复算。

```bash
export PYTHONPATH=backend:.
study_dir="local-data/agent-study/2026-05-21_2026-11-20"
experiment_dir="${study_dir}-frequency"
.venv/bin/python -m scripts.collect_option_expiries --study "$study_dir" --out "$experiment_dir"
.venv/bin/python -m scripts.frequency_replay --source "$study_dir" --output "$experiment_dir"
.venv/bin/python -m scripts.frequency_control --study "$study_dir" --out "$experiment_dir"
.venv/bin/python -m scripts.term_study --study "$study_dir" --out "$experiment_dir/term.json"
.venv/bin/python -m scripts.term_study --study "$study_dir" --anchor option --out "$experiment_dir/term-option.json"
```

首次运行排序实验会产生新的模型回执。相同协议下，给 `scripts.frequency_replay` 加上 `--settle-frozen` 即可仅用已有回执重算。摘要接口为 `GET /api/workbench/frequency-study`，`replay`、`control`、`term` 和 `term-option` 子路径提供完整账目。

现场研究可读取独立纸面账户快照 `local-data/forward-paper-account.json`。快照格式为 `forward_paper_account.v1`，`as_of` 和 `valid_until` 均带时区，`sleeves` 下的 A、B、C 各有 `cash`、`equity` 与 `positions`。持仓逐笔列出 `product`、`contract`、`quantity` 和 `open_cost`。快照有效时按各组当前现金、权益和已占预算筛选。缺少有效快照时，档案明确提示资金和持仓未知，仅按参考本金给出条件计划。半年滚动基线另从已核验的历史账本接续，三个组合独立模拟结算。

## 从行情到策略

```text
React 工作台 ──提交研究──▶ FastAPI ──创建任务──▶ SQLite
                             │
                             ├──▶ 临时工作区 · 行情取证 · Codex 分析
                             │                    │
                             │           结构化策略与反证结论
                             │                    ▼
                             └──◀── Schema、业务规则与时点校验
                             │
React 工作台 ◀──SSE 进度 / 状态轮询──┴──▶ 已校验策略与公开任务事件
```

独立的报价接口显示品种连续行情。正式研究按实际交割月绑定证据，全市场逐品种记录覆盖与缺口。工作台保留焦点结论，并逐条校验和保存同批次的买方期权机会。证据不足时保存「等待」及原因，供下一轮复核。

## 研究档案与复盘

1. 在「研究档案与回放」选择有记录的研究。原始取证会展示实际合约、行情时点、获取时点、来源和日线切片。可下载行情原件并复算 SHA-256，策略记录保留证据缺口和反证。
2. 选择北京时间的回放截止点。回放以获取时点控制可见性，用原决策时点复核策略，并查询随后积累的同合约归档行情。如后来样本触及原失效价，页面会显示对应观测。样本间走势保留为未知。
3. 全市场机会卡显示入选理由、反证、证据缺口、触发、失效和复核时间。两轮同范围都返回候选清单时，档案会列出新增、移出和关键条件变化。

SQLite 保存任务状态、策略和已校验的机会。DuckDB 保存采集原件及带时点的行情，用于按合约及可用时间查询。两者均随应用在本机运行，文件为 `local-data/qice.sqlite3` 和 `local-data/research.duckdb`。已有的策略与行情档案可继续查看。备份时先停止服务，再复制 `local-data/`。

研究档案中的单笔复盘，以已存证的行情对照原策略的时间与合约约束；半年仿真则逐个交易日调用模型并单独记账。历史日线缓存须通过独立完整性校验，缺失时按证据缺口处理。工作台用于研究，交易账户与订单执行在系统范围之外。
