# Qice Derivatives Lab · 期策

**本地运行的商品期货与买方期权研究工作台。** 期策把行情取证、Codex 分析、策略校验和结果回看接成一条研究流程。每次分析固定品种与时点，记录可用证据及缺口，再由程序校验结论是否满足发布条件。当前配置覆盖中国商品市场的 22 个品种。

`React · TypeScript`　`FastAPI · Python`　`SQLite`　`DuckDB`　`Codex CLI`

## 快速体验

需要 macOS 或 Linux、Python 3.12+、Node.js 22+ 和 pnpm。首次启动会联网安装依赖和构建界面。

```bash
git clone https://github.com/aniwar1/qice-derivatives-lab.git
cd qice-derivatives-lab
./start.sh
```

打开 <http://127.0.0.1:8000>。首次启动即可浏览策略计划和品种观察项。要采集行情和生成研究结论，先安装 Codex CLI 并执行 `codex login`，再选择「运行全市场研究」或在品种页点击「运行单品种分析」。

服务只监听回环地址，按 `Ctrl+C` 停止。端口冲突时可用 `./start.sh --port 8080`。可用 `PYTHON_BIN=python3.12 ./start.sh` 指定解释器。行情查询和生成新策略需要联网，已保存的策略可离线回看。

## 工作台

| 入口 | 能看到什么 |
| --- | --- |
| 策略总览 | 并排比较多因子方向买权、技术择强买权和事件驱动宽跨式。切换累计收益率与组合权益，查看逐日数据、期末收益率和最大回撤。 |
| 策略计划 | 每套策略的候选排序、合约选择、仓位预算与退出规则。导入回测后，可按交易日核对期权腿、开平仓和期末损益。 |
| 品种研究 | 搜索 22 个品种，查看实际月份合约走势图、各品种的供需与催化观察项、已归档的技术、资金、期权证据及分析结论。 |
| 研究档案 | 查看研究记录、下载行情原件、核对合格机会，并按指定时点回放。 |

历史曲线读取本机的 `local-data/backtests/2026-10/`。从已有批次复制 `equity.csv`、`summary.json`、`source-manifest.json`、`market.json.gz` 和 `days/*.json` 即可导入。服务会检查市场快照摘要、逐日账目和策略摘要的一致性。公共仓库提供代码和计划，回测数据目录由本机管理。回测采用公开开盘价模拟成交，期末收益包含未平仓浮盈亏。

## 从行情到策略

```text
React 工作台 ──提交研究──▶ FastAPI ──创建任务──▶ SQLite
                             │
                             ├──▶ 临时工作区 · 行情取证 · Codex 分析
                             │                    │
                             │           结构化策略与反证结论
                             │                    ▼
                             └──◀── Schema、业务规则与时点校验
                             │
React 工作台 ◀──SSE 进度 / 状态轮询──┴──▶ 已校验策略与公开任务事件
```

独立的报价接口显示品种连续行情。正式研究按实际交割月绑定证据，全市场逐品种记录覆盖与缺口。工作台保留焦点结论，并逐条校验和保存同批次的买方期权机会。证据不足时保存「等待」及原因，供下一轮复核。

## 工程设计

| 问题 | 实现 | 源码入口 |
| --- | --- | --- |
| 怎样约束模型输出？ | Codex 在每轮临时工作区取证并返回结构化策略。服务复验品种、月份、证据时点、反证结论和执行权限，通过后才更新最新策略。 | [任务编排与校验](backend/app/service.py)、[输出契约](backend/schemas/codex_strategy_decision.agent.schema.json) |
| 半根日线能支持什么结论？ | 对夜盘后的部分日线，验证交易所日历、数据覆盖和采集时点。满足条件时可用于条件触发，确认突破要求完成日线。 | [日线证据校验](scripts/session_aware_bar.py)、[边界回归](tests/test_session_aware_bar.py) |
| 两次点击或服务重启会怎样？ | SQLite 部分唯一索引限制同一时间只有一个活动任务。结果与完成事件同事务提交，重启后将遗留任务标记为中断，并继续提供最近已完成的策略。 | [任务存储](backend/app/db.py)、[状态回归](backend/tests/test_store.py) |
| 浏览器断线如何恢复？ | SSE 推送公开进度，前端通过任务状态轮询补偿断线，任务结果由服务端保存。 | [SSE](backend/app/sse.py)、[前端状态处理](frontend/src/App.tsx) |

## 研究档案与复盘

1. 在「研究档案与回放」选择有记录的研究。原始取证会展示实际合约、行情时点、获取时点、来源和日线切片。可下载行情原件并复算 SHA-256，策略记录保留证据缺口和反证。
2. 选择北京时间的回放截止点。回放以获取时点控制可见性，用原决策时点复核策略，并查询随后积累的同合约归档行情。如后来样本触及原失效价，页面会显示对应观测。样本间走势保留为未知。
3. 全市场机会卡显示入选理由、反证、证据缺口、触发、失效和复核时间。两轮同范围都返回候选清单时，档案会列出新增、移出和关键条件变化。

SQLite 保存任务状态、策略和已校验的机会。DuckDB 保存采集原件及带时点的行情，用于按合约及可用时间查询。两者均随应用在本机运行，文件为 `local-data/qice.sqlite3` 和 `local-data/research.duckdb`。已有的策略与行情档案可继续查看。备份时先停止服务，再复制 `local-data/`。

回放以已存证的行情为输入，对照当时策略中的时间与合约约束。它不重跑模型，也不从归档间隔推定成交。历史日线缓存须通过独立完整性校验，缺失时按证据缺口处理。工作台用于研究，交易账户与订单执行在系统范围之外。
